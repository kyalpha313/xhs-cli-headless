# v0.8.6 Agent Skill Design

## Goal

`0.8.6` turns `xhs-cli-headless` into the single installable artifact for both humans and AI agents: the CLI remains the implementation layer, while bundled skill docs and helper commands explain how agents should authenticate, recover sessions, route requests, and avoid unstable capabilities.

## Release Scope

This release focuses on five outcomes:

1. Bump the package to `0.8.6`.
2. Merge the useful parts of `kyalpha313/xhs-cli-skill` into this repository as bundled agent-facing documentation and helper scripts.
3. Make session expiration actionable for agents: errors should point to `xhs login`, `xhs auth doctor`, `xhs auth import`, and `xhs auth import-fields` in a structured way.
4. Improve read-only note handling where it matters for agents: short links, standard profile note URLs, HTML fallback parsing, and clear image/comment boundaries.
5. Refresh Chinese README and release notes as user-facing best-practice docs, following the practical style of `glata-cli`.

Publishing to PyPI/GitHub is prepared by this branch but should only be executed after tests and smoke validation pass.

## Architecture

The CLI remains the source of truth. The skill layer is bundled under `skills/` and `references/`, with scripts under `scripts/` only wrapping the installed `xhs` command rather than importing private modules. This mirrors the `glata-cli` pattern of shipping both executable behavior and agent guidance in one repository.

Authentication recovery is centralized in exception/error rendering rather than copied into every command. Business commands continue to call `get_client()`, but login/session errors include an agent-readable recovery plan.

Note reading keeps the existing API-first behavior when `xsec_token` is available, then falls back to HTML parsing. HTML parsing is expanded to support current mobile/SSR structures and to return note-only images rather than unrelated recommendation thumbnails.

## Capability Boundaries

Default supported capabilities remain conservative:

- Auth/session: `login`, `status`, `whoami`, `auth doctor`, `auth inspect`, imports, `logout`
- Read/discovery: `search`, `search-user`, `topics`, `feed`, `hot`, `read`, `comments`, `board`, `my-notes`, `unread`
- Interactions: `like`, `favorite`, `unfavorite`, `comment`, `reply`, `delete-comment`, `follow`, `unfollow`

This release does not promote unstable commands such as `delete`, `sub-comments`, `user`, `user-posts`, `favorites`, `likes`, or full notification feeds.

## Testing

Automated tests should cover:

- Short-link/profile URL parsing to note ID.
- HTML fallback extraction of title, description, author, note images, and embedded first-page comments from current SSR/mobile-like state.
- Structured login recovery hints for missing and expired sessions.
- Bundled skill/helper script presence and smoke behavior.
- README/release version consistency.

## Documentation

The README should be written for users, not repository maintainers. It should lead with what the CLI can do, how to install, how an agent should handle login, and what to do when a session expires. Capability boundaries should be explicit and avoid overpromising.

Release notes should explain user-visible changes, migration impact, and validation status.
